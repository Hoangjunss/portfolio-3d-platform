**Revised:** 2026-09-20 — rewritten before hand-off. The previous draft used
`package com.portfolio.platform.analytics;` (pre-spec-5.1 feature packages) in every code block,
put a public and an admin route in one controller, had **no validation at all** on an

**Goal:** Three things, in this order.

## Global Constraints

- Backend must run within `-Xmx350m` (spec section 7 RAM budget) — no unbounded in-memory collections, use pagination on list endpoints.
- All admin-mutating endpoints (`POST`/`PUT`/`DELETE` under `/api/admin/**`) require a valid JWT with role `ADMIN` or `EDITOR`; only `ADMIN` may manage users and settings.
- Every admin CREATE/UPDATE/DELETE must write an `audit_logs` row (spec section 6); every 5xx response must write a `system_error_logs` row (spec section 8).
- **Nothing below 5xx may write a `system_error_logs` row.** Broken by R-01 (plan 04), again by
  C-01 (plan 06), and again today — see task 1. Any new exception type MUST get an explicit
  `@ExceptionHandler` in the same commit that introduces it.
- Public GET endpoints (`templates`, `content-sections`) are Redis-cached with cache-aside invalidation on write (spec section 5).
- Public POST endpoints (`leads`, `analytics/events`, `auth/login`) are rate-limited via Bucket4j (spec section 5). **Rate limiting itself is plan 09** — do not add Bucket4j here.
- `analytics_events.ip_hash` stores a hash of the IP, never the raw IP (spec section 6).
- Templates are static-exported Next.js sites served by Nginx on `<slug>.portfolio.com`, no per-template runtime process (spec sections 4, 7).
- No comments restating what code does; only comments explaining non-obvious "why".
- **Package layout follows spec section 5.1 (layered), not feature packages.** Read 5.1 before
  creating any class. A `service/XService.java` entry in a file list always means the pair
  `service/XService.java` (interface) + `service/impl/XServiceImpl.java` (implementation).
- **Controllers never touch a Repository or a Converter**, schedulers and the `@RestControllerAdvice`
  never touch a Repository. `LayerDependencyTest` enforces this and will fail the build.
- Request bodies are `form/*Form`, response bodies and inter-layer data are `dto/*Dto`
  (spec 5.1, Form vs Dto ownership). Entities live in `model/` with no suffix.
- **Constructor injection only** (spec 5.1). No field `@Autowired`.
- Spring Boot here is **3.3.4** — the test mock annotation is
  `org.springframework.boot.test.mock.mockito.MockBean`, not `@MockitoBean` (3.4+).
- Surefire filters are **comma**-separated: `-Dtest='A,B'`. `-Dtest='A+B'` runs nothing and still
  exits 1, which reads like a test failure. Before every mutation check run
  `rm -f backend/target/surefire-reports/*.txt` so a stale report can't be misread as a result.

## Task 1: Stop the `system_error_logs` pump on malformed request bodies

**This is live today and reachable with no login.** Probe run on `HEAD` before writing this plan:

```
POST /api/public/leads  body: {"name":"x", BROKEN
  PROBE_MALFORMED_STATUS=500   PROBE_MALFORMED_LOGDELTA=1

POST /api/public/leads  body: {"name":"x","email":"a@b.co","sourceTemplateId":"not-a-number"}
  PROBE_BADTYPE_STATUS=500     PROBE_BADTYPE_LOGDELTA=1
```

`HttpMessageNotReadableException` has no handler, so it falls into
`@ExceptionHandler(Exception.class)` → 500 + one `system_error_logs` row. Anyone with `curl` can
loop this against `/api/public/leads` or `/api/auth/login` and fill the table. C-01 at least
required an EDITOR account; this needs nothing.

**Files:**
- Modify: `backend/src/main/java/com/portfolio/platform/exception/GlobalExceptionHandler.java`
- Modify: `backend/src/test/java/com/portfolio/platform/exception/GlobalExceptionHandlerTest.java`

### Design decisions this task must follow

**(a) Fix the class of bug, not the one instance.** Every Spring MVC exception that means "the
caller sent something wrong" is currently a 500 + a log row. Handle them explicitly **and** add
a safety net so the next one is not a fourth repeat:

In `handleUnexpected`, before logging, check whether the exception is an
`org.springframework.web.ErrorResponse` carrying a 4xx status. If it is, return that status
with **no** log row. Most Spring MVC client-fault exceptions implement this interface in
Spring 6. Explicit handlers still come first — the net is for the ones nobody thought of.

**(b) Do not widen this into a `ResponseEntityExceptionHandler` migration.** Extending it would
change every existing error body to `ProblemDetail` and break the one-shape-for-every-response
contract plan 04 established. Keep `ApiErrorDto`.

### Design decisions this task must follow

**(c) `eventType` is an enum, not a free String.** `enums/AnalyticsEventType { PAGE_VIEW,
TEMPLATE_CLICK, DEMO_OPEN }`, stored `@Enumerated(EnumType.STRING)`. A free String on a public
endpoint means any caller writes whatever 32 characters they like into the table, and the admin
dashboard then renders attacker-chosen labels. An unknown enum value in the JSON body becomes
`HttpMessageNotReadableException` → **400 via task 1**, which is exactly why task 1 comes first.

**(d) Every field bounded to its column, like plan 07 decision (e).** `event_type VARCHAR(32)`
(enum covers it), `session_id VARCHAR(128) NOT NULL` → `@NotBlank @Size(max = 128)`. This is an
unauthenticated endpoint; an unbounded field is a 500 + a log row, which is the very thing task 1
is fixing.

**(e) `userAgent` and `referrer` come from headers, and are truncated, not rejected.** Drop them
from `TrackEventForm` — read `User-Agent` and `Referer` in the controller and pass them to the
service. Two reasons: a body field lets the client report a different UA from the one it actually
sent, and a 600-character UA (they exist) must not fail the request. Truncate to the column
widths — 512 and 1024 — in the service, with a WHY comment. Analytics rejecting real traffic is
worse than analytics storing a clipped UA.

**(f) `templateId` must be checked, like plan 07 decision (f).** `analytics_events.template_id`
is `REFERENCES templates(id)`. An unknown id is a `DataIntegrityViolationException` → 500 + log
row from an anonymous caller. Check `templateRepository.existsById` — **but the service may not
call `TemplateRepository` and `AnalyticsEventRepository` both?** It may: `service → repository`
is allowed for any repository. Throw `InvalidRequestException("Unknown template")`.

**(g) The IP hash must be keyed — an unsalted SHA-256 of an IP is not anonymisation.** IPv4 is
2^32 values; anyone holding the database can brute-force the entire space in minutes and recover
every raw IP, which makes `ip_hash` a raw IP with extra steps and breaks the spec's own
requirement. Use **HMAC-SHA256** with a secret from `config/AnalyticsProperties`
(`analytics.ip-hash-secret`, env `ANALYTICS_IP_HASH_SECRET`, dev default a fixed dev-only string
matching the `jwt.access-secret` convention already in `application.yml`). Base64 the result and
keep it inside `VARCHAR(128)` — Base64 of 32 bytes is 44 characters, fine.

**(h) Behind nginx, `getRemoteAddr()` is the proxy.** Plan 16 puts nginx in front, and then every
event would hash to the same value, making the column useless. Read the first hop of
`X-Forwarded-For` when the header is present, else `getRemoteAddr()`. Add a WHY comment stating
the trade-off plainly: a client can forge `X-Forwarded-For`, so this value is **not** evidence of
anything — it is a coarse uniqueness signal for analytics only, and must never be used for
security decisions or rate limiting. **Plan 09 must not reuse this method for rate limiting.**

**(i) Close T-02 here.** `PAGE_VIEW` with a `templateId` increments `templates.view_count`, the
mirror of what `TEMPLATE_CLICK` already does for `click_count`. Add
`TemplateRepository.incrementViewCount` as a `@Modifying @Query` copy of `incrementClickCount`,
plus the service method. Without this, plan 12's frontend renders a permanent 0 and `viewCount`
in `TemplateDto` is a lie.

**(j) The summary queries need indexes.** `countByEventType` and the group-by run full scans on
the one table that grows per visitor. Add `V3__analytics_indexes.sql`:

```sql
CREATE INDEX idx_analytics_events_event_type ON analytics_events (event_type);
CREATE INDEX idx_analytics_events_template_id ON analytics_events (template_id);
CREATE INDEX idx_analytics_events_created_at ON analytics_events (created_at);
```

State clearly in the commit body that **this migration has never been executed** — the suite runs
H2 with Flyway disabled and there is no Docker on this machine. It joins open finding R-03 for
whoever gets a real Postgres first.
