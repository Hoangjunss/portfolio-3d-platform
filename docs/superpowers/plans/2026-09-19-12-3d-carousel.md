## Global Constraints

- Backend must run within `-Xmx350m` — no unbounded in-memory collections, pagination on list endpoints.
- All admin-mutating endpoints under `/api/admin/**` require a valid JWT with `ADMIN` or `EDITOR`; only `ADMIN` may manage users and settings.
- Every admin CREATE/UPDATE/DELETE writes an `audit_logs` row; every 5xx writes a `system_error_logs` row.
- **Nothing below 5xx may write a `system_error_logs` row.**
- **Every backend error response is an `ApiErrorDto` JSON body.**
- Public GET endpoints are Redis-cached with cache-aside invalidation on write; public POST endpoints are rate-limited.
- `analytics_events.ip_hash` stores a hash of the IP, never the raw IP.
- Templates are static-exported Next.js sites served by Nginx on `<slug>.portfolio.com`. **The main portfolio app is not static** — it has `/admin` and a dynamic home page, so it runs a Next server.
- No comments restating what code does; only comments explaining non-obvious "why".
- **Backend layout follows spec 5.1.** Mapping lives in `converter/`, never a static factory on a DTO. **Controllers never touch a Repository.** `LayerDependencyTest` is a hand-written import scanner, **not ArchUnit** (finding A-04) — it is blind to fully-qualified references, so a green build is not proof. **Do not widen its allow-list** (finding A-06).
- **Constructor injection only.** Spring Boot 3.3.4 — `org.springframework.boot.test.mock.mockito.MockBean`.
- Surefire filters are **comma**-separated; `rm -f backend/target/surefire-reports/*.txt` before every mutation check.
- **Report every mutation result, including the ones that stay GREEN.** Two of the last three hand-offs left the commit body empty or partial.
- **Do not run `npm install` with `--legacy-peer-deps`.** If npm reports ERESOLVE after a version change, delete `node_modules` and `package-lock.json` and install clean — an in-place major bump makes npm compare against the stale tree and report a conflict that is not real. That happened twice during the V-02 upgrade.

## Task 1: Let the public site resolve a template thumbnail

**The carousel cannot render a thumbnail today.** `TemplateDto` carries `thumbnailMediaId` (a
`Long`), `MediaDto.url` holds the actual path, and `MediaController` is
`@RequestMapping("/api/admin/media")` with **only** a `@PostMapping`. There is no public endpoint
that turns an id into a URL, and `/api/admin/**` requires a JWT — so an anonymous visitor has no
route to the image at all. This is the same class of gap the readiness survey found for
`GET /api/admin/leads`.

### Design decisions

**(a) Add `thumbnailUrl` to `TemplateDto`; do not add a public media endpoint.** Two reasons.
A per-image lookup would be one HTTP round trip per card on the landing page — the exact N+1 the
RAM/latency constraints exist to avoid. And a public `GET /api/public/media/{id}` would expose
every uploaded file by enumerable id, including media never attached to a public template.
Resolving it server-side keeps the blast radius at "thumbnails of active templates".

**(b) Resolve in the service, not the converter.** `TemplateConverterImpl` would need
`MediaRepository`, and `converter → repository` is **not** in the allow-list (spec 5.1 and
`LayerDependencyTest`). Load the media rows in `TemplateServiceImpl` and pass the resolved URL
into the converter as a second argument.

**(c) One query, not one per template.** `listActive()` already returns a list; collect the
non-null `thumbnailMediaId` values and fetch them with a single `findAllById`, then map. A
per-row `findById` inside a loop is the N+1 this decision exists to prevent — and it would be
invisible in tests, so **the mutation check below is what makes it real**.

**(d) `thumbnailUrl` is `null` when there is no thumbnail.** Do not invent a placeholder path on
the backend; the frontend decides what to draw for a missing image (decision (i)).

**(e) The cache must not go stale.** `listActive()` is `@Cacheable` (plan 05). The cached value
now embeds a media URL, so uploading a replacement thumbnail must evict it. Check what
`@CacheEvict` already exists on the template write paths and extend it only if needed — **report
what you found either way**.

## Task 2: The carousel

**Files:**

- Create: `frontend/lib/session.ts`, `frontend/lib/session.test.ts`
- Create: `frontend/components/TemplateCarousel.tsx`, `TemplateCarousel2D.tsx`,
  `TemplateCarousel3D.tsx`, `TemplatePreviewModal.tsx`
- Create: `frontend/components/TemplateCarousel.test.tsx`
- Modify: `frontend/app/page.tsx`

### Design decisions

**(f) `sessionId` must be generated on the client and persisted.** The old draft called
`crypto.randomUUID()` inside the server component, so **every page render produced a new id** —
`analytics_events.session_id` would never correlate two events, which is the column's entire
purpose. Put it in `lib/session.ts`: read `sessionStorage`, generate and store on miss, return it.
Server-side it must return `null` and no event fires until the client has one.

**(g) A `PAGE_VIEW` event must actually be sent.** The old draft tracked only `TEMPLATE_CLICK`
and `DEMO_OPEN`. But plan 08 wired `templates.view_count` to `PAGE_VIEW` specifically, and closing
T-02 rested on that. With no `PAGE_VIEW` ever sent, `view_count` stays 0 forever and T-02 is
re-opened in practice while looking closed on paper. Fire one `PAGE_VIEW` per mounted session.

**(h) The 2D carousel is the server-rendered default; 3D is a client upgrade.** The old draft
returned `null` until a `useEffect` probe finished, so the server sent an empty page: nothing for
crawlers, nothing without JS, and a blank first paint on the one page meant to sell the product.
Render `TemplateCarousel2D` on the server, then swap in `TemplateCarousel3D` after the WebGL probe
succeeds. The fallback stops being a fallback and becomes the floor.

**(i) Missing thumbnails must not break the canvas.** `useTexture` suspends and throws on a
failed load. Cards whose `thumbnailUrl` is `null` render a coloured plane with the template name
as an HTML overlay; cards with a URL render inside `<Suspense>`. A single 404 must not blank the
carousel.

**(j) A failed `getTemplates()` must not blank the landing page.** It runs in a server component
with a 5s timeout (plan 11 decision (i)). If the backend is down, the page must still render its
shell and an empty state — `try/catch` around the call, not an unhandled throw.

**(k) The preview `iframe` gets `sandbox` and `referrerPolicy`.** It embeds
`https://{subdomain}.portfolio.com`, which is our own static export, but the frame should not be
able to navigate the top window or run same-origin script against us. Use
`sandbox="allow-scripts allow-same-origin"` deliberately and say in a comment why each token is
there. `subdomain` is admin-authored, not visitor-authored, so it is not the C-04 class — but it
still ends up in an `href` and a `src`, so it must never be interpolated anywhere a scheme could
be injected.

**(l) Replace "verify manually in a browser" with `npm run build`.** Nothing in this pipeline can
drive a browser, so a manual step is a step that silently never happens. `npm run build` is the
real gate: it type-checks, runs the App Router's server render, and fails on a missing `Suspense`
or a server/client boundary mistake — exactly the errors this task can introduce.
