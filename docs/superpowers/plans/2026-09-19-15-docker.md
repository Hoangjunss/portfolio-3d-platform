**Goal:** Package the backend and frontend as Docker images and compose the full stack (Nginx, frontend, backend, Postgres, Redis) with hard RAM limits that fit the 2GB VPS budget.

**Architecture:** Multi-stage Dockerfiles (build stage discarded, slim JRE/Node runtime kept) and a single `docker-compose.yml` at the repo root with per-service `deploy.resources.limits.memory`.

**Tech Stack:** Docker, Docker Compose, `eclipse-temurin:21-jre-alpine`, `node:20-alpine`.

**Spec:** `docs/superpowers/specs/2026-09-19-portfolio-3d-platform-design.md`

**Depends on:** `2026-09-19-10-user-management.md` (backend complete); `2026-09-19-14-admin-dashboard-crud.md` (frontend complete).

## Global Constraints

- Backend must run within `-Xmx350m` (spec section 7 RAM budget) — no unbounded in-memory collections, use pagination on list endpoints.
- All admin-mutating endpoints (`POST`/`PUT`/`DELETE` under `/api/admin/**`) require a valid JWT with role `ADMIN` or `EDITOR`; only `ADMIN` may manage users and settings.
- Every admin CREATE/UPDATE/DELETE must write an `audit_logs` row (spec section 6); every 5xx response must write a `system_error_logs` row (spec section 8).
- Public GET endpoints (`templates`, `content-sections`) are Redis-cached with cache-aside invalidation on write (spec section 5).
- Public POST endpoints (`leads`, `analytics/events`, `auth/login`) are rate-limited via Bucket4j (spec section 5).
- `analytics_events.ip_hash` stores a hash of the IP, never the raw IP (spec section 6).
- Templates are static-exported Next.js sites served by Nginx on `<slug>.portfolio.com`, no per-template runtime process (spec sections 4, 7).
- No comments restating what code does; only comments explaining non-obvious "why".

## Decisions settled during plan review

- **(a) `NEXT_PUBLIC_API_BASE_URL` is a build argument, not a runtime environment variable.**
  Next.js substitutes `process.env.NEXT_PUBLIC_*` with string literals when `npm run build` runs
  and bakes them into the client bundle. A runtime `environment:` entry cannot change code that
  is already compiled — the bundle would ship `apiClient.ts`'s fallback `http://localhost:8080`
  and every visitor's browser would call their own machine. This is the most expensive mistake
  available in this plan because nothing looks wrong: build green, container Up, health green.
- **(b) Services declare both `image:` and `build:`.** `build:` is for local development;
  `image:` is what plan 17's CI pushes and what `docker compose pull` on the VPS resolves.
  Without `image:` the whole CI/CD pipeline is inert (Z-21).
- **(c) Startup fails loudly when a secret still holds its development default.** A-08 has been
  open since plan 08 and its current failure mode is silent: production would run on
  `dev-only-analytics-secret-change-me`, which is published in this repository. The guard is a
  bean with a test, not a line of documentation.
- **(d) `depends_on` uses `condition: service_healthy`.** The list form only orders container
  starts; it does not wait for Postgres to accept connections, and `ddl-auto: validate` plus
  Flyway both hit the database during boot.
- **(e) The runtime image carries no devDependencies.** Next's `output: "standalone"` emits a
  minimal server bundle; copying the whole build stage ships vitest, typescript and the Tailwind
  toolchain into a 400MB-capped container.

- [ ] **Step 2: Create `backend/Dockerfile`**

```dockerfile
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn -B -q dependency:go-offline
COPY src ./src
RUN mvn -B -q package -DskipTests

FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
RUN addgroup -S app && adduser -S app -G app
COPY --from=build /app/target/*.jar app.jar
USER app
EXPOSE 8080
# -Xmx350m is the spec section 7 budget. -Xss256k keeps per-thread stacks small because Tomcat
# holds a thread per in-flight request and the container ceiling is only 450m.
ENTRYPOINT ["java", "-Xmx350m", "-Xss256k", "-jar", "app.jar"]
```

- [ ] **Step 3: Create `frontend/Dockerfile`**

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
# Decision (a): NEXT_PUBLIC_* is inlined here, at build time. Setting it as a runtime
# environment variable in compose has no effect on an already-compiled client bundle.
ARG NEXT_PUBLIC_API_BASE_URL
ENV NEXT_PUBLIC_API_BASE_URL=$NEXT_PUBLIC_API_BASE_URL
RUN npm run build

FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
ENV NODE_OPTIONS="--max-old-space-size=300"
COPY --from=build /app/.next/standalone ./
COPY --from=build /app/.next/static ./.next/static
EXPOSE 3000
CMD ["node", "server.js"]
```

`npm ci`, not `npm install`: the project pinned exact versions to close V-01/V-02, and
`npm install` is free to resolve past them.

If you add a `frontend/public/` directory later, it needs its own `COPY` line — standalone output
does not include it.

**`JWT_REFRESH_SECRET` is deliberately absent.** `JwtProperties` is
`record JwtProperties(String accessSecret, long accessTtlMinutes, long refreshTtlDays)` — there
is no refresh secret, because refresh tokens are opaque random strings stored in the database,
not signed JWTs. The previous copy of this plan passed one anyway, which told operators to manage
a secret that does not exist while the one that does — `ANALYTICS_IP_HASH_SECRET` — was missing
entirely.

`${VAR:?message}` makes compose refuse to start instead of substituting an empty string.

Run `mvn -f backend/pom.xml test` — must FAIL, `SecretsGuard` does not exist. Then create
`backend/src/main/java/com/portfolio/platform/config/SecretsGuard.java`:

```java
@Component
public class SecretsGuard {

    private static final Map<String, String> DEV_DEFAULTS = Map.of(
            "jwt.access-secret", "dev-only-access-secret-change-me-32bytes",
            "analytics.ip-hash-secret", "dev-only-analytics-secret-change-me");

    private final Environment environment;

    public SecretsGuard(Environment environment) {
        this.environment = environment;
    }

    // A-08: both secrets have defaults that are published in this repository, and nothing failed
    // when the environment did not override them. The old failure mode was silent -- the app
    // booted happily and every analytics ip_hash was reversible by anyone who could read the repo.
    @PostConstruct
    public boolean verify() {
        if (!List.of(environment.getActiveProfiles()).contains("prod")) {
            return true;
        }
        DEV_DEFAULTS.forEach((key, devValue) -> {
            if (devValue.equals(environment.getProperty(key))) {
                throw new IllegalStateException(
                        "Refusing to start with the development default for " + key
                                + ". Set it via the environment before deploying.");
            }
        });
        return true;
    }
}
```

`SecretsGuard` lives in `config/`, which spec 5.1's layer rules exempt (T-05) — confirm
`LayerDependencyTest` stays green.

Run `mvn -f backend/pom.xml test` again — must PASS, 135/135.
