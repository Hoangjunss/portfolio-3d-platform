> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `agency` demo template site (site #2 of 29, `display_order` 2) — its own

`Hero` → `ItemGrid`(work, with page-level filter tabs) → `ItemGrid`(capabilities) → `Footer` from
`@portfolio/template-kit`, and its "Save to shortlist" interactive feature backed by
`useLocalCollection`.

**Architecture:** This plan is one of 29 site plans (interactive-demo spec §9, plans 31-59) and is
plan 32 in that numbering (site #2, "agency"). It has a **hard prerequisite: plan 30** (`template-kit`
package + `useLocalCollection` + the 15 kit components + the `templates` table's 29-row seed,
including the `agency` / `agency` / `display_order=2` row) **must already be complete** — this plan
does not build, fork, or modify anything inside `template-kit/`; it only imports from
`@portfolio/template-kit` as a dependency, per the parent spec's "no bespoke per-template
component" rule.

**Tech Stack:** Next.js 15 / React 19, `output: 'export'` static site, TypeScript, Vitest +
Testing Library + jsdom for the interaction tests, the `hallmark` skill (greenfield path) for
Task 1's design pass.

**Spec:** `docs/superpowers/specs/2026-09-20-site-agency-design.md` (this site's own thin spec —
§2 section composition, §3 seed data, §4 shortlist data flow, §5 Hallmark design brief) and, one
level up, `docs/superpowers/specs/2026-09-20-interactive-demo-templates-design.md` (§3.1

### Design decisions

**(a) Filter tabs are page-level state, not a kit prop.** Per this site's own spec §2, `ItemGrid`
takes only `items`/`columns` (plan 30 Task 3's actual scaffolded shape) — `WorkSection.tsx` is a
`'use client'` component holding `activeCategory` state, rendering plain `<button>` tab controls
(one per `WorkCategory`, plus "All"), and passing `ItemGrid` a filtered, category-stripped
`GridItem[]` derived from `WORK_ITEMS`. This keeps `template-kit` untouched.

**(b) Static-first render, per interactive-demo spec §3.1's render-pattern rule.** `page.tsx`
itself is a server component that imports `WORK_ITEMS`/`CAPABILITIES` directly and passes the
**full, unfiltered** work list to `WorkSection` as a prop — `WorkSection`'s "All" tab is the
default `activeCategory`, so first paint (including the static HTML export) shows every work item,
identical to what a static `ItemGrid` alone would render. Filtering only changes what's visible
after client-side hydration, never gates the initial visible content (this rule carries over
unchanged into Task 3's shortlist logic too — see that task's design decisions).

**(c) `thumbnail.webp` is a placeholder image checked in at scaffold time**, not final art — a
solid-color or simple placeholder WEBP passing `check-thumbnail.mjs`'s magic-byte check, replaced
later by an admin-uploaded real screenshot per parent spec §6 (the admin upload step is out of
scope for this plan, same as every other site plan).

```tsx
// templates/agency/app/WorkSection.tsx
'use client';
import { useState } from 'react';
import { ItemGrid } from '@portfolio/template-kit';
import { WORK_CATEGORIES, type WorkItem } from '../data/work';

export interface WorkSectionProps {
  items: WorkItem[];
}

export function WorkSection({ items }: WorkSectionProps) {
  const [activeCategory, setActiveCategory] = useState<'all' | WorkItem['category']>('all');

  const visible = items.filter(
    (item) => activeCategory === 'all' || item.category === activeCategory,
  );

  return (
    <section id="work" className="agency-work-section">
      <div className="agency-filter-tabs" role="tablist" aria-label="Filter work by category">
        <button
          type="button"
          aria-pressed={activeCategory === 'all'}
          onClick={() => setActiveCategory('all')}
        >
          All
        </button>
        {WORK_CATEGORIES.map((category) => (
          <button
            key={category.key}
            type="button"
            aria-pressed={activeCategory === category.key}
            onClick={() => setActiveCategory(category.key)}
          >
            {category.label}
          </button>
        ))}
      </div>
      <ItemGrid
        items={visible.map((item) => ({
          id: item.id,
          title: item.title,
          description: item.description,
          image: item.image,
        }))}
        columns={3}
      />
    </section>
  );
}
```

**Interfaces:**

  and 5).
- Produces: nothing consumed by a later task — this is the last implementation task in this plan.

### Design decisions

**(d) One `useLocalCollection` instance, held in `WorkSection`, passed down.** Per this site's spec
§4 data flow, `WorkSection` (already a client component from Task 2) calls
`useLocalCollection<{id: string; title: string; savedAt: string}>('agency-shortlist', [])` once at
its top level — not inside the per-item map, and not a second instance inside `ShortlistPanel` —
so there is exactly one source of truth for the shortlist, matching the hook's `storageKey`
isolation contract (plan 30 Task 4, mutation M12).

**(e) Save is a toggle, not an always-add.** Clicking "Save" on an already-saved item calls
`remove(item.id)` instead of `add(...)` again — checked via `items.some(saved => saved.id ===
item.id)` before deciding which mutation to call. This matches this site's spec §4 step 3.

**(f) Per-item Save buttons live in `WorkSection`'s own render, next to each `ItemGrid`-rendered
card, not inside `ItemGrid`.** Since `ItemGrid`'s `GridItem` has no action-button slot (plan 30
Task 3's actual scaffolded shape), `WorkSection` renders its own `<ul>` of save-button controls
absolument positioned/laid adjacent to the grid via CSS (Hallmark's Task 1 layout call decides the
exact visual treatment) rather than forking `ItemGrid` — each button keyed by `item.id`, labelled
via `aria-label` (`Save ${item.title}` / `Remove ${item.title} from shortlist`) so it stays
independently testable and accessible regardless of the final visual layout.

```tsx
  const { items: shortlist, add, remove } = useLocalCollection<ShortlistEntry>('agency-shortlist', []);

  const visible = items.filter(
    (item) => activeCategory === 'all' || item.category === activeCategory,
  );

  function toggleSave(item: WorkItem) {
    const alreadySaved = shortlist.some((saved) => saved.id === item.id);
    if (alreadySaved) {
      remove(item.id);
    } else {
      add({ id: item.id, title: item.title, savedAt: new Date().toISOString() });
    }
  }

  return (
    <section id="work" className="agency-work-section">
      <div className="agency-filter-tabs" role="tablist" aria-label="Filter work by category">
        <button
          type="button"
          aria-pressed={activeCategory === 'all'}
          onClick={() => setActiveCategory('all')}
        >
          All
        </button>
        {WORK_CATEGORIES.map((category) => (
          <button
            key={category.key}
            type="button"
            aria-pressed={activeCategory === category.key}
            onClick={() => setActiveCategory(category.key)}
          >
            {category.label}
          </button>
        ))}
      </div>

      <div className="agency-work-grid-with-actions">
        <ItemGrid
          items={visible.map((item) => ({
            id: item.id,
            title: item.title,
            description: item.description,
            image: item.image,
          }))}
          columns={3}
        />
        <ul className="agency-save-buttons">
          {visible.map((item) => {
            const saved = shortlist.some((entry) => entry.id === item.id);
            return (
              <li key={item.id}>
                <button type="button" onClick={() => toggleSave(item)}>
                  {saved ? `Remove ${item.title} from shortlist` : `Save ${item.title}`}
                </button>
              </li>
            );
          })}
        </ul>
      </div>

      <ShortlistPanel items={shortlist} onRemove={remove} />
    </section>
  );
}
```
