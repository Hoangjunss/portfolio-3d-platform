# Personal Portfolio Demo Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `portfolio` demo template site (`templates/portfolio/`) — site #8 of the 29
site plans under the interactive-demo templates program. Run a real per-site Hallmark design pass,
scaffold the static Next.js export composing `Hero` → `Timeline`(experience, vertical) →
`PhotoGallery`(single project set) → `Footer` from `@portfolio/template-kit`, and build its
"leave feedback" interactive feature by reusing `CommentThread` on `useLocalCollection`.

**Architecture:** This plan is plan 38 in the interactive-demo spec's §9 execution order — one of
plans 31-59, each independent once plan 30 lands. It has one hard prerequisite:
`2026-09-20-30-template-kit-scaffold.md` must be complete and committed (`@portfolio/template-kit`
built, tested, exporting `Hero`, `Timeline`, `PhotoGallery`, `Footer`, `CommentThread`,
`useLocalCollection`, `TemplateTheme`/`assertValidTheme` from its barrel `src/index.ts`). This plan
does not modify `template-kit` itself — it only consumes it. Task 1 runs a real Hallmark design
session (not a scaffold/placeholder step) and commits its own theme output; Task 2 scaffolds the
Next.js app and static composition; Task 3 builds the project-feedback interactive feature (reusing
`CommentThread`, the same component the blog category uses) and its interaction test, plus the
design-scoring self-audit.

**Tech Stack:** Next.js 15 / React 19 static export (`output: 'export'`), TypeScript, Vitest +
Testing Library + jsdom for the interaction test, `@portfolio/template-kit` as a local workspace
dependency. No backend change — this plan touches nothing under `backend/`.

**Spec:** `docs/superpowers/specs/2026-09-20-site-portfolio-design.md` (section composition, seed
data shape/content, interactive-feature data flow and the `CommentThread` reuse rationale, Hallmark
design brief) plus the two specs it is scoped by:
`docs/superpowers/specs/2026-09-20-interactive-demo-templates-design.md` (§3.1 `useLocalCollection`
contract, §3.2 row #8 the leave-feedback feature, §3.3 `CommentThread`'s shared-component listing,
§5 per-site Hallmark requirement, §7 the build+interaction test gate, §8 the 10-criterion design
scoring gate, §9 execution order) and
`docs/superpowers/specs/2026-09-20-template-design-system-design.md` (§4 component behavior/prop
contracts including `Timeline`'s orientation prop and `PhotoGallery`'s layout/lightbox props, §6
folder/thumbnail/slug convention).

**(d) `ProjectFeedbackSection` is a client component (`'use client'`)** mounted inside the

field in the kit component); this site's wrapper supplies a fixed `'Portfolio visitor'` author when
building the stored `ProjectFeedback` record, exactly as spec'd in §4.1/§4.4.

```tsx
'use client';
import { useLocalCollection, CommentThread } from '@portfolio/template-kit';

interface ProjectFeedback {
  id: string;
  author: string;
  text: string;
  at: string;
}

const FEEDBACK_SEED: ProjectFeedback[] = [];

export function ProjectFeedbackSection() {
  const { items, add, reset } = useLocalCollection<ProjectFeedback>(
    'portfolio-project-feedback',
    FEEDBACK_SEED,
  );

  async function handleSubmit(text: string) {
    add({
      id: crypto.randomUUID(),
      author: 'Portfolio visitor',
      text,
      at: new Date().toISOString(),
    });
  }

  return (
    <section className="portfolio-project-feedback" id="feedback">
      <h2>Leave feedback</h2>
      <CommentThread comments={items} onSubmit={handleSubmit} />
      <button type="button" onClick={reset}>Reset demo data</button>
    </section>
  );
}
```
