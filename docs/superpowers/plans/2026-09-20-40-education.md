# Education Demo Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `education` demo template site (`templates/education/`) — site #10 of the 29
site plans under the interactive-demo templates program. Run a real per-site Hallmark design pass,
scaffold the static Next.js export composing `Hero` → `ItemGrid`(courses) → curriculum accordion
(page-level `<details>`/`<summary>`, not a kit component) → `Footer` from `@portfolio/template-kit`,
and build its "Enroll" → "My courses" interactive feature on `useLocalCollection` +
`SavedItemsPanel`.

**Architecture:** This plan is plan 40 in the interactive-demo spec's §9 execution order (one of
plans 31-59, independent of every other site plan once plan 30 lands). It has one hard
prerequisite: `2026-09-20-30-template-kit-scaffold.md` must be complete and committed
(`@portfolio/template-kit` built, tested, exporting `Hero`, `ItemGrid`, `SavedItemsPanel`,
`Footer`, `useLocalCollection`, `TemplateTheme`/`assertValidTheme` from its barrel `src/index.ts`).
This plan does not modify `template-kit` itself — it only consumes it. Task 1 runs a real Hallmark
design session (not a scaffold/placeholder step) and commits its own theme output; Task 2 scaffolds
the Next.js app and static composition (including the page-level curriculum accordion); Task 3
builds the enroll interactive feature and its interaction test, plus the design-scoring
self-audit.

**Tech Stack:** Next.js 15 / React 19 static export (`output: 'export'`), TypeScript, Vitest +
Testing Library + jsdom for the interaction test, `@portfolio/template-kit` as a local workspace
dependency. No backend change — this plan touches nothing under `backend/`.

**Spec:** `docs/superpowers/specs/2026-09-20-site-education-design.md` (section composition, seed
data shape/content, curriculum-accordion page-level detail, enroll interactive-feature data flow,
Hallmark design brief) plus the two specs it is scoped by:
`docs/superpowers/specs/2026-09-20-interactive-demo-templates-design.md` (§3.1
`useLocalCollection` contract, §3.2 row #10 the enroll/"My courses" feature, §3.3
`SavedItemsPanel` contract, §5 per-site Hallmark requirement, §7 the build+interaction test gate,
§8 the 10-criterion design scoring gate, §9 execution order) and
`docs/superpowers/specs/2026-09-20-template-design-system-design.md` (§3 taxonomy row #10, §4
component behavior/prop contracts, §6 folder/thumbnail/slug convention).

### Design decisions

**(e) `EnrollmentSection` is a client component (`'use client'`)** mounted inside the otherwise
static-exported `page.tsx`, per the Global Constraints render-pattern rule — it owns the
`useLocalCollection` call, renders the "My courses" `SavedItemsPanel`, and exposes a
`renderEnrollButton(course)` render-prop function that `page.tsx` threads into
`CurriculumAccordion`'s `renderAction` prop so each `<details>` block gets a working "Enroll"
button without `CurriculumAccordion` itself needing to become a client component. The rest of the
page (`Hero`, `ItemGrid`, `Footer`) stays server/static-rendered.

**(f) "My courses" uses `SavedItemsPanel` directly, unlike Corporate's plan-31 plain-list
precedent** — per `docs/superpowers/specs/2026-09-20-site-education-design.md` §4's documented
rationale: enrolling is choosing from a fixed catalog and unenrolling is a legitimate expected
action, which is exactly `SavedItemsPanel`'s save/shortlist/remove contract (spec §4 contrasts this
with Corporate's callback-request list, which isn't "removable from a catalog" in the same sense).

**(g) The enroll handler is idempotent** — clicking "Enroll" again on an already-enrolled course
must not create a duplicate `education-enrollments` row (spec §4's idempotency requirement); checked
via `items.some(i => i.id === course.id)` before calling `add`.

```tsx
'use client';
import { useLocalCollection, SavedItemsPanel } from '@portfolio/template-kit';
import type { Course } from '../data/seed';

export interface EducationEnrollment {
  id: string;
  title: string;
  enrolledAt: string;
}

const ENROLLMENTS_SEED: EducationEnrollment[] = [];

export interface EnrollmentSectionProps {
  courses: Course[];
}

export function EnrollmentSection({ courses }: EnrollmentSectionProps) {
  const { items, add, remove } = useLocalCollection<EducationEnrollment>(
    'education-enrollments',
    ENROLLMENTS_SEED,
  );

  function handleEnroll(course: Course) {
    if (items.some((enrollment) => enrollment.id === course.id)) return;
    add({ id: course.id, title: course.title, enrolledAt: new Date().toISOString() });
  }

  return (
    <section className="education-enrollment" aria-label="My courses">
      <h2>My courses</h2>
      <SavedItemsPanel
        items={items}
        emptyLabel="You haven't enrolled in any courses yet — pick one below."
        onRemove={remove}
        renderItem={(enrollment) => (
          <>
            <strong>{enrollment.title}</strong>{' '}
            <time dateTime={enrollment.enrolledAt}>
              {new Date(enrollment.enrolledAt).toLocaleDateString('vi-VN')}
            </time>
          </>
        )}
      />
```
