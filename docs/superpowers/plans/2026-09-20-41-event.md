# Event Demo Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `event` demo template site (`templates/event/`) — site #11 of the 29 site plans
under the interactive-demo templates program. Run a real per-site Hallmark design pass, scaffold the
static Next.js export composing `Hero` → `Timeline`(agenda, horizontal) → `PeopleGrid`(speakers) →
`PricedItemGrid`(ticket tiers) → `Footer` from `@portfolio/template-kit`, and build its "Add to my
schedule" → "My schedule" interactive feature on `useLocalCollection` + `SavedItemsPanel`.

**Architecture:** This plan is plan 41 in the interactive-demo spec's §9 execution order (one of
plans 31-59, independent of every other site plan once plan 30 lands). It has one hard
prerequisite: `2026-09-20-30-template-kit-scaffold.md` must be complete and committed
(`@portfolio/template-kit` built, tested, exporting `Hero`, `Timeline`, `PeopleGrid`,
`PricedItemGrid`, `Footer`, `SavedItemsPanel`, `useLocalCollection`,
`TemplateTheme`/`assertValidTheme` from its barrel `src/index.ts`). This plan does not modify
`template-kit` itself — it only consumes it. Task 1 runs a real Hallmark design session (not a
scaffold/placeholder step) and commits its own theme output; Task 2 scaffolds the Next.js app and
static composition; Task 3 builds the add-to-schedule interactive feature and its interaction test,
plus the design-scoring self-audit.

**Tech Stack:** Next.js 15 / React 19 static export (`output: 'export'`), TypeScript, Vitest +
Testing Library + jsdom for the interaction test, `@portfolio/template-kit` as a local workspace
dependency. No backend change — this plan touches nothing under `backend/`.

**Spec:** `docs/superpowers/specs/2026-09-20-site-event-design.md` (section composition, seed data
shape/content, the page-local "Add" control row rationale, add-to-schedule interactive-feature data
flow, Hallmark design brief) plus the two specs it is scoped by:
`docs/superpowers/specs/2026-09-20-interactive-demo-templates-design.md` (§3.1 `useLocalCollection`
contract, §3.2 row #11 the add-to-schedule/"personal schedule view" feature, §3.3 `SavedItemsPanel`
contract, §5 per-site Hallmark requirement, §7 the build+interaction test gate, §8 the
10-criterion design scoring gate, §9 execution order) and
`docs/superpowers/specs/2026-09-20-template-design-system-design.md` (§3 taxonomy row #11, §4
component behavior/prop contracts, §6 folder/thumbnail/slug convention).

### Design decisions

**(e) `ScheduleSection` is a client component (`'use client'`)** mounted inside the otherwise
static-exported `page.tsx`, per the Global Constraints render-pattern rule — it owns the

**(f) "My schedule" uses `SavedItemsPanel` directly, relabeled via its `emptyLabel`/heading copy** —
per `docs/superpowers/specs/2026-09-20-site-event-design.md` §3.3's documented rationale: adding an
agenda entry to one's personal schedule, and later removing it, is exactly `SavedItemsPanel`'s
save-from-a-fixed-catalog/remove contract (same reasoning Education used for "My courses," plan 40
§4) — not Corporate's plain-list "visitor-authored form submission" case.

**(g) The add-to-schedule handler is idempotent** — clicking "Add" again on an entry already in the
visitor's schedule must not create a duplicate `event-my-schedule` row (spec §3.3's idempotency
requirement); checked via `items.some(i => i.id === entry.id)` before calling `add`.

```tsx
'use client';
import { useLocalCollection, SavedItemsPanel } from '@portfolio/template-kit';
import type { TimelineEntry } from '@portfolio/template-kit';

export interface ScheduleEntry {
  id: string;
  title: string;
  addedAt: string;
}

const SCHEDULE_SEED: ScheduleEntry[] = [];

export interface ScheduleSectionProps {
  agenda: TimelineEntry[];
}

export function ScheduleSection({ agenda }: ScheduleSectionProps) {
  const { items, add, remove } = useLocalCollection<ScheduleEntry>('event-my-schedule', SCHEDULE_SEED);

  function handleAdd(entry: TimelineEntry) {
    if (items.some((scheduled) => scheduled.id === entry.id)) return;
    add({ id: entry.id, title: entry.title, addedAt: new Date().toISOString() });
  }

  return (
    <section className="event-schedule" aria-label="Schedule builder">
      <h2>My schedule</h2>
      <SavedItemsPanel
        items={items}
        emptyLabel="Your schedule is empty — add sessions from the agenda below."
        onRemove={remove}
        renderItem={(entry) => (
          <>
            <strong>{entry.title}</strong>{' '}
            <time dateTime={entry.addedAt}>{new Date(entry.addedAt).toLocaleTimeString('vi-VN')}</time>
          </>
        )}
      />
      <ul className="event-schedule-add-row" aria-label="Add sessions to your schedule">
        {agenda.map((entry) => (
          <li key={entry.id}>
            <span>{entry.date}</span>
            <span>{entry.title}</span>
            <button type="button" onClick={() => handleAdd(entry)}>
              {`Add ${entry.title} to my schedule`}
            </button>
          </li>
        ))}
      </ul>
    </section>
  );
}
```
