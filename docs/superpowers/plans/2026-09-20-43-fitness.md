# Fitness/Gym Demo Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `fitness` demo template site (`templates/fitness/`) — site #13 of 29 under the
interactive-demo templates program. Run a real per-site Hallmark design pass, scaffold the static
Next.js export composing `Hero` → class-schedule table (read-only `RecordTable` reuse) →
`PeopleGrid`(trainers) → `PricedItemGrid`(membership) → `Footer` from `@portfolio/template-kit`,
and build its "Book a class" interactive feature on `useLocalCollection` + `SavedItemsPanel`.

**Architecture:** This plan is plan 43 in the interactive-demo spec's §9 execution order — one of
plans 31-59, independent of every other site plan once plan 30 lands. Hard prerequisite:
`2026-09-20-30-template-kit-scaffold.md` must be complete and committed
(`@portfolio/template-kit` built, tested, exporting `Hero`, `RecordTable`, `PeopleGrid`,
`PricedItemGrid`, `Footer`, `SavedItemsPanel`, `useLocalCollection`,
`TemplateTheme`/`assertValidTheme` from its barrel `src/index.ts`). This plan does not modify
`template-kit` itself — it only consumes it, per the task brief's explicit instruction not to add
a new kit component for the schedule table. Task 1 runs a real Hallmark design session and commits
its own theme output; Task 2 scaffolds the Next.js app and static composition; Task 3 builds the
book-a-class interactive feature, its interaction test, and the design-scoring self-audit.

**Tech Stack:** Next.js 15 / React 19 static export (`output: 'export'`), TypeScript, Vitest +
Testing Library + jsdom for the interaction test, `@portfolio/template-kit` as a local workspace
dependency. No backend change — this plan touches nothing under `backend/`.

**Spec:** `docs/superpowers/specs/2026-09-20-site-fitness-design.md` (section composition,
`RecordTable` read-only reuse rationale, seed data shape/content, booking data flow, Hallmark
design brief) plus the two specs it is scoped by:
`docs/superpowers/specs/2026-09-20-interactive-demo-templates-design.md` (§3.1
`useLocalCollection` contract, §3.2 row #13 the book-a-class feature, §3.3 `SavedItemsPanel`

### Design decisions

**(e) `BookingSection` is a client component (`'use client'`)** mounted directly beneath the
static-exported schedule `RecordTable` in `page.tsx`, per the Global Constraints render-pattern
rule — it owns the `useLocalCollection` call, renders one "Book" button per `SCHEDULE` entry, and
renders `SavedItemsPanel` (relabeled "My bookings") for the visitor's own bookings. The rest of
the page (`Hero`, the static schedule table, `PeopleGrid`, `PricedItemGrid`, `Footer`) stays
server/static-rendered.

**(f) "Book" buttons live in `BookingSection`, not inside `RecordTable`'s row actions** — per
`2026-09-20-site-fitness-design.md` §2.1's documented rationale (booking is additive, not
`RecordTable`'s single-row-mutation `onEdit`/`onDelete` semantics). `BookingSection` maps over the
same `SCHEDULE` array Task 2 passed into `RecordTable`, rendering its own list of "Book" controls
positioned directly under the static table so the visual pairing (row → book action) is clear
without either component needing to know about the other.

**(g) "My bookings" uses `SavedItemsPanel` directly**, per
`2026-09-20-site-fitness-design.md` §4.2 — `items` = the hook's `items`, `emptyLabel` = a "no
bookings yet" message, `onRemove` = the hook's `remove(id)` (this is the "cancel a booking"
action), `renderItem` = a function rendering `className` + `time` + a formatted `bookedAt`.

import { render, screen, fireEvent, waitFor } from '@testing-library/react';
import { BookingSection } from './BookingSection';

beforeEach(() => {

```tsx
'use client';
import { useLocalCollection, SavedItemsPanel } from '@portfolio/template-kit';
import { SCHEDULE } from '../data/seed';

interface Booking {
  id: string;
  className: string;
  time: string;
  bookedAt: string;
}

const BOOKINGS_SEED: Booking[] = [];

export function BookingSection() {
  const { items, add, remove, reset } = useLocalCollection<Booking>(
    'fitness-bookings',
    BOOKINGS_SEED,
  );

  function handleBook(className: string, time: string) {
    add({
      id: crypto.randomUUID(),
      className,
      time,
      bookedAt: new Date().toISOString(),
    });
  }

  return (
    <section className="fitness-booking">
      <h2>Book a class</h2>
      <ul className="fitness-booking-actions">
        {SCHEDULE.map((entry) => (
          <li key={entry.id}>
            <span>{entry.className} — {entry.time}</span>
            <button type="button" onClick={() => handleBook(entry.className, entry.time)}>
              Book
            </button>
          </li>
        ))}
      </ul>
      <aside aria-label="My bookings">
        <h3>My bookings</h3>
        <SavedItemsPanel
          items={items}
          emptyLabel="No bookings yet — book a class above and it will appear here."
          onRemove={remove}
          renderItem={(booking: Booking) =>
            `${booking.className} — ${booking.time} (booked ${new Date(booking.bookedAt).toLocaleString('vi-VN')})`
          }
        />
        <button type="button" onClick={reset}>Reset demo data</button>
      </aside>
    </section>
  );
}
```
