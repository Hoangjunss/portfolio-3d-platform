# Beauty/Salon Demo Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `beauty` demo template site (`templates/beauty/`) — site #17 of the 29 site
plans under the interactive-demo templates program. Run a real per-site Hallmark design pass,
scaffold the static Next.js export composing `Hero` → `PricedItemGrid`(treatments) →
`InquiryForm`(booking) → `Footer` from `@portfolio/template-kit`, and build its "Book your visit"
→ "Your bookings" interactive feature on `useLocalCollection`.

**Architecture:** This plan is plan 47 in the interactive-demo spec's §9 execution order — one of
plans 31-59, independent of every other site plan once plan 30 lands. It has one hard prerequisite:
`2026-09-20-30-template-kit-scaffold.md` must be complete and committed (`@portfolio/template-kit`
built, tested, exporting `Hero`, `PricedItemGrid`, `InquiryForm`, `Footer`, `useLocalCollection`,
`TemplateTheme`/`assertValidTheme` from its barrel `src/index.ts`). This plan does not modify
`template-kit` itself — it only consumes it. Task 1 runs a real Hallmark design session (not a
scaffold/placeholder step) and commits its own theme output; Task 2 scaffolds the Next.js app and
static composition; Task 3 builds the booking interactive feature and its interaction test, plus
the design-scoring self-audit.

**Tech Stack:** Next.js 15 / React 19 static export (`output: 'export'`), TypeScript, Vitest +
Testing Library + jsdom for the interaction test, `@portfolio/template-kit` as a local workspace
dependency. No backend change — this plan touches nothing under `backend/`.

**Spec:** `docs/superpowers/specs/2026-09-20-site-beauty-design.md` (section composition, seed data
shape/content, interactive-feature data flow, Hallmark design brief) plus the two specs it is
scoped by: `docs/superpowers/specs/2026-09-20-interactive-demo-templates-design.md` (§3.1
`useLocalCollection` contract, §3.2 row #17 the booking feature, §5 per-site Hallmark requirement,
§7 the build+interaction test gate, §8 the 10-criterion design scoring gate, §9 execution order)
and `docs/superpowers/specs/2026-09-20-template-design-system-design.md` (§3 taxonomy row #17, §4
component behavior/prop contracts, §6 folder/thumbnail/slug convention).

### Design decisions

**(d) `BookingSection` is a client component (`'use client'`)** mounted inside the otherwise
static-exported `page.tsx`, per the Global Constraints render-pattern rule — it owns the
`useLocalCollection` call and renders both the `InquiryForm` and the "Your bookings" list; the rest
of the page (`Hero`, `PricedItemGrid`, `Footer`) stays server/static-rendered.

**(e) The "Your bookings" panel is a plain ordered list, not `SavedItemsPanel`** — per
`docs/superpowers/specs/2026-09-20-site-beauty-design.md` §4.3's documented rationale
(`SavedItemsPanel`'s remove-from-catalog contract doesn't fit a visitor-authored form submission).
No new `template-kit` component is added for this — the list is page-local JSX, not a kit export.

**(f) `preferredDate` and `preferredTime` are collected as two separate form fields but merged
into one `preferredDate` string before being stored** — per spec §4.3, the booking hook's
persisted shape (`{id, name, phone, treatment, preferredDate}`) has no separate time field; the
merge happens in the `onSubmit` handler, not by widening the persisted shape.

```tsx
'use client';
import { useLocalCollection, InquiryForm, type InquiryField } from '@portfolio/template-kit';

interface BeautyBooking {
  id: string;
  name: string;
  phone: string;
  treatment: string;
  preferredDate: string;
}

const BOOKING_SEED: BeautyBooking[] = [];

const BOOKING_FIELDS: InquiryField[] = [
  { name: 'treatment', label: 'Preferred treatment', type: 'text', required: true },
  { name: 'preferredDate', label: 'Preferred date', type: 'text', required: true },
  { name: 'preferredTime', label: 'Preferred time', type: 'text', required: true },
];

export function BookingSection() {
  const { items, add, reset } = useLocalCollection<BeautyBooking>('beauty-bookings', BOOKING_SEED);

  async function handleSubmit(values: Record<string, string>) {
    add({
      id: crypto.randomUUID(),
      name: values.name,
      phone: values.phone,
      treatment: values.treatment,
      preferredDate: `${values.preferredDate} ${values.preferredTime}`.trim(),
    });
  }

  return (
    <section className="beauty-booking">
      <h2>Book your visit</h2>
      <InquiryForm fields={BOOKING_FIELDS} submitLabel="Book your visit" onSubmit={handleSubmit} />
      <aside aria-label="Your bookings">
        <h3>Your bookings</h3>
        {items.length === 0 ? (
          <p>No bookings yet — submit the form above and it will appear here.</p>
        ) : (
          <ol>
            {items.map((booking) => (
              <li key={booking.id}>
                <strong>{booking.name}</strong> — {booking.treatment} ({booking.preferredDate})
              </li>
            ))}
          </ol>
        )}
        <button type="button" onClick={reset}>Reset demo data</button>
      </aside>
    </section>
  );
}
```
