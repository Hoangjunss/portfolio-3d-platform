# CRM Agency Demo Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `crm-agency` demo template site (`templates/crm-agency/`) — a full internal
dashboard app, not a marketing landing page. Run a real per-site Hallmark design pass for a
cool-hue/grotesque-sans internal-tool aesthetic; scaffold a fake-login gate + dashboard shell with
a 3-item sidebar (Contacts, Pipeline, Activity Log); build the Contacts screen on `RecordTable`,
the Deals/Pipeline screen on `KanbanBoard`, and the Activity Log screen on `RecordTable` with
cross-screen auto-append logging, each backed by its own `useLocalCollection`.

**Architecture:** This plan is one of the 29 site plans in the interactive-demo spec's §9 execution
order (§4.3's `crm-agency` row). Hard prerequisite: `2026-09-20-30-template-kit-scaffold.md` must
be complete and committed (`@portfolio/template-kit` exporting `RecordTable`, `KanbanBoard`,
`useLocalCollection`, `TemplateTheme`/`assertValidTheme` from its barrel `src/index.ts`). This plan
does not modify `template-kit` itself. Unlike the landing-page site plans (e.g. plan 31), this
site's page structure is a login gate + dashboard shell, not `Hero`-led section composition — Task
2 therefore scaffolds the login/shell/state layer (all four `useLocalCollection` instances and the
shared activity-logging helper) up front, with the three screens as placeholders; Tasks 3-5 each
replace one placeholder with its real screen and wire mutations through the shared logger already
built in Task 2.

**Tech Stack:** Next.js 15 / React 19 static export (`output: 'export'`), TypeScript, Vitest +
Testing Library + jsdom, `@portfolio/template-kit` as a local workspace dependency. No backend
change — this plan touches nothing under `backend/`.

**Spec:** `docs/superpowers/specs/2026-09-20-site-crm-agency-design.md` (page structure, fake-login
behavior, sidebar nav, seed data for contacts/deals/activity log, pipeline stages, auto-append
triggers, Hallmark design brief) plus the two specs it is scoped by:
`docs/superpowers/specs/2026-09-20-interactive-demo-templates-design.md` (§3.1 `useLocalCollection`
contract, §3.3 `KanbanBoard`/`RecordTable` behavior, §4.3 the CRM category's structural definition,
§5 per-site Hallmark requirement, §7 the build+interaction test gate, §8 the 10-criterion design
scoring gate, §9 execution order) and
`docs/superpowers/plans/2026-09-20-30-template-kit-scaffold.md` (Task 4's `useLocalCollection`
implementation, Task 5's `KanbanBoard`/`RecordTable` exact prop shapes this plan consumes verbatim).

  the accepted trade-off is that a *returning, already-logged-in* visitor sees a brief
  login-screen-then-dashboard flash on each fresh load while the effect reads their stored session,
  rather than an empty/loading state. This is documented here so Task 2 does not attempt to "fix"

### Design decision

**(a) This is a real Hallmark session, not a scaffold placeholder**, run for an **internal-tool**
aesthetic, not a landing-page aesthetic — the session's brief is
`docs/superpowers/specs/2026-09-20-site-crm-agency-design.md` §5 ("Hallmark design brief"): the
assigned mood (cool anchor hue, grotesque-sans display, master spec §4.3), the three research
directions (Swiss/International-Style grid systems adapted to software chrome;
creative-agency-brand-carried-into-tool; dark-capable developer-tool-adjacent dashboard chrome),
and the explicit differentiation target — this site must read as clearly distinct from
`crm-realestate` (also cool-hued, but humanist-sans and a different visual attitude) even though
both share the "cool" mood family. The session may land anywhere its research supports, as long as
the result clears every criterion in master spec §8 at Task 5 time (particularly #1 anti-generic,
#2 typographic craft, #3 color coherence, #10 distinctiveness against the other 28 sites).

**(b) Token scope is wider than a landing page's** — beyond `TemplateTheme`'s 3 required fields
(`accentHue`, `displayFont`, `bodyFont`), this site's `globals.css` needs data-table-specific
tokens (row hover/selected state, sidebar active-item state, Kanban column background/gutter,
focus-visible ring) since master spec §8 criterion #7 (accessibility — keyboard-navigable Kanban
drag-equivalent `<select>` controls, visible focus states) and criterion #4 (layout/spacing rhythm
in a data-dense context) apply just as much to a dashboard as to a landing page.

### Design decisions

**(c) `data/seed.ts` holds all three seed arrays plus `STAGES`**, copied verbatim from
`docs/superpowers/specs/2026-09-20-site-crm-agency-design.md` §3.1-§3.4 — all 10 contacts, all 8
deals, all 5 stages, all 6 activity-log seed rows; not trimmed, not invented beyond the spec.

**(d) Login state is a `useLocalCollection<Session>('crm-agency-session', [])` collection holding
zero or one row**, not a boolean flag — chosen so login state reuses the exact same
localStorage-backed primitive as every other piece of state in this app (master spec §4.3: "Fake
login and its data are both `localStorage`-only"), rather than inventing a second, bespoke
persistence mechanism just for the login flag. `Session = { id: 'current', email, loggedInAt }`.
`isLoggedIn` is derived as `session.items.length > 0`. Logging in calls `session.add(...)`;
logging out (via "Reset demo data" only — see design decision (e)) calls `session.reset()`, which
re-seeds to `[]` since the seed passed to this hook instance is `[]`.

**(e) "Reset demo data" is the only logout path, per spec §1.1/§4** — `DashboardApp`'s
`handleReset` calls `reset()` on all four `useLocalCollection` instances (contacts, deals,
activityLog, session) in one handler, in the same click, matching the spec's "one action does
both" requirement exactly. There is no separate logout button.

**(f) `lib/activity.ts`'s `createActivityLogger(add)` returns a bound `logActivity` function**
that fills in `id` (`crypto.randomUUID()`) and `at` (`new Date().toISOString()`) so every call site
(Task 3's `ContactsScreen`, Task 4's `DealsScreen`, and `DashboardApp`'s own manual-note handler for
Task 5) only supplies the semantic fields (`type`, `note`, optional `contactId`/`dealId`) — never
reimplements id/timestamp generation per screen.

```typescript
import { describe, it, expect, vi } from 'vitest';
import { createActivityLogger } from './activity';

describe('createActivityLogger', () => {
  it('calls add with a generated id, an ISO at timestamp, and the given fields', () => {
    const add = vi.fn();
    const logActivity = createActivityLogger(add);
    logActivity({ type: 'contact_created', note: 'New contact added: Test', contactId: 'c1' });

    expect(add).toHaveBeenCalledTimes(1);
    const entry = add.mock.calls[0][0];
    expect(entry.type).toBe('contact_created');
    expect(entry.note).toBe('New contact added: Test');
    expect(entry.contactId).toBe('c1');
    expect(typeof entry.id).toBe('string');
    expect(entry.id.length).toBeGreaterThan(0);
    expect(() => new Date(entry.at).toISOString()).not.toThrow();
  });

  it('never reuses the same id across two calls', () => {
    const add = vi.fn();
    const logActivity = createActivityLogger(add);
    logActivity({ type: 'note', note: 'first' });
    logActivity({ type: 'note', note: 'second' });
    expect(add.mock.calls[0][0].id).not.toBe(add.mock.calls[1][0].id);
  });
});
```

```tsx
  window.localStorage.clear();
```

```tsx
'use client';
import { useState, type FormEvent } from 'react';
import { RecordTable } from '@portfolio/template-kit';
import type { Contact } from '../data/seed';
import type { LogActivityFn } from '../lib/activity';

export interface ContactsScreenProps {
  contacts: Contact[];
  onAdd: (contact: Contact) => void;
  onUpdate: (id: string, patch: Partial<Contact>) => void;
  onRemove: (id: string) => void;
  logActivity: LogActivityFn;
}

const COLUMNS = [
  { key: 'name', label: 'Name' },
  { key: 'company', label: 'Company' },
  { key: 'email', label: 'Email' },
  { key: 'phone', label: 'Phone' },
  { key: 'tagsDisplay', label: 'Tags' },
];

interface ContactFormValues {
  name: string;
  company: string;
  email: string;
  phone: string;
  tags: string;
}

const EMPTY_FORM: ContactFormValues = { name: '', company: '', email: '', phone: '', tags: '' };

export function ContactsScreen({ contacts, onAdd, onUpdate, onRemove, logActivity }: ContactsScreenProps) {
  const [creating, setCreating] = useState(false);
  const [editingId, setEditingId] = useState<string | null>(null);
  const [form, setForm] = useState<ContactFormValues>(EMPTY_FORM);

  function startCreate() {
    setForm(EMPTY_FORM);
    setCreating(true);
    setEditingId(null);
  }

  function startEdit(contact: Contact) {
    setForm({ name: contact.name, company: contact.company, email: contact.email, phone: contact.phone, tags: contact.tags.join(', ') });
    setEditingId(contact.id);
    setCreating(false);
  }

  function cancelForm() {
    setCreating(false);
    setEditingId(null);
  }

  function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const tags = form.tags.split(',').map((tag) => tag.trim()).filter(Boolean);

    if (creating) {
      const contact: Contact = { id: crypto.randomUUID(), name: form.name, company: form.company, email: form.email, phone: form.phone, tags };
      onAdd(contact);
      logActivity({ contactId: contact.id, type: 'contact_created', note: `New contact added: ${contact.name} (${contact.company})` });
    } else if (editingId) {
      onUpdate(editingId, { name: form.name, company: form.company, email: form.email, phone: form.phone, tags });
      logActivity({ contactId: editingId, type: 'contact_updated', note: `Contact updated: ${form.name}` });
    }
    setCreating(false);
    setEditingId(null);
  }

  function handleDelete(id: string) {
    const contact = contacts.find((c) => c.id === id);
    onRemove(id);
    logActivity({ contactId: id, type: 'contact_deleted', note: `Contact removed: ${contact?.name ?? id}` });
  }

  const rows = contacts.map((contact) => ({ ...contact, tagsDisplay: contact.tags.join(', ') }));
  const showForm = creating || editingId !== null;

  return (
    <section aria-label="Contacts">
      <h2>Contacts</h2>
      <button type="button" onClick={startCreate}>Add contact</button>
      {showForm ? (
        <form aria-label={creating ? 'Add contact' : 'Edit contact'} onSubmit={handleSubmit}>
          <label>
            Name
            <input value={form.name} onChange={(event) => setForm({ ...form, name: event.target.value })} required />
          </label>
          <label>
            Company
            <input value={form.company} onChange={(event) => setForm({ ...form, company: event.target.value })} required />
          </label>
          <label>
            Email
            <input type="email" value={form.email} onChange={(event) => setForm({ ...form, email: event.target.value })} required />
          </label>
          <label>
            Phone
            <input value={form.phone} onChange={(event) => setForm({ ...form, phone: event.target.value })} />
          </label>
          <label>
            Tags (comma-separated)
            <input value={form.tags} onChange={(event) => setForm({ ...form, tags: event.target.value })} />
          </label>
          <button type="submit">Save</button>
          <button type="button" onClick={cancelForm}>Cancel</button>
        </form>
      ) : null}
      <RecordTable columns={COLUMNS} rows={rows} onEdit={startEdit} onDelete={handleDelete} />
    </section>
  );
}
```

```tsx
  const [title, setTitle] = useState('');
  const [contactId, setContactId] = useState(contacts[0]?.id ?? '');
  const [valueVnd, setValueVnd] = useState('');

  function handleMove(id: string, newStage: string) {
    const deal = deals.find((d) => d.id === id);
    onUpdate(id, { stage: newStage as DealStage, updatedAt: new Date().toISOString() });
    logActivity({
      dealId: id,
      contactId: deal?.contactId,
      type: 'deal_stage_changed',
      note: `${deal?.title ?? id} moved to ${STAGE_LABEL[newStage as DealStage] ?? newStage}`,
    });
  }

  function handleCreate(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const deal: Deal = {
      id: crypto.randomUUID(),
      contactId,
      title,
      valueVnd: Number(valueVnd) || 0,
      stage: 'new',
      updatedAt: new Date().toISOString(),
    };
    onAdd(deal);
    logActivity({ dealId: deal.id, contactId: deal.contactId, type: 'deal_created', note: `New deal opened: ${deal.title}` });
    setTitle('');
    setValueVnd('');
    setCreating(false);
  }

  return (
    <section aria-label="Pipeline">
      <h2>Pipeline</h2>
      <button type="button" onClick={() => setCreating((value) => !value)}>Add deal</button>
      {creating ? (
        <form aria-label="Add deal" onSubmit={handleCreate}>
          <label>
            Title
            <input value={title} onChange={(event) => setTitle(event.target.value)} required />
          </label>
          <label>
            Contact
            <select value={contactId} onChange={(event) => setContactId(event.target.value)}>
              {contacts.map((contact) => <option key={contact.id} value={contact.id}>{contact.name}</option>)}
            </select>
          </label>
          <label>
            Value (VND)
            <input type="number" value={valueVnd} onChange={(event) => setValueVnd(event.target.value)} required />
          </label>
          <button type="submit">Save</button>
        </form>
      ) : null}
      <KanbanBoard
        columns={STAGES}
        items={deals}
        renderItem={(deal) => `${deal.title} — ${formatVnd(deal.valueVnd)} — ${contactName(contacts, deal.contactId)}`}
        onMove={handleMove}
      />
    </section>
  );
}
```

### Design decisions

**(l) The full auto-append wiring, end to end:** Task 2 built `createActivityLogger` and the one
`activityLogCollection` instance in `DashboardApp`. Task 3's `ContactsScreen` and Task 4's
`DealsScreen` each received the *same* bound `logActivity` function as a prop and call it from
their own mutation handlers (`handleSubmit`/`handleDelete` in `ContactsScreen`,
`handleMove`/`handleCreate` in `DealsScreen`) — this is the "shared helper function both call" from
spec §3.4, already in place before this task starts. This task's job is only to (a) build the
screen that displays `activityLogCollection.items`, and (b) wire the one mutation that belongs to
this screen itself — the manual "Add note" form, which also calls `logActivity` (with
`type: 'note'`, no `contactId`/`dealId`) since a manual note has the same shape needs as any other
entry; per spec §3.4 this is the one call that does not itself trigger a *further* log entry (it
already is one).

**(m) `ActivityLogScreen` sorts `entries` by `at` descending before passing them to `RecordTable`**
— per spec §3.4's clarification that display order (not storage order) is what guarantees
most-recent-first, since `useLocalCollection.add()` (plan 30 Task 4) always appends.

**(n) Edit/delete on this screen apply generically to any entry (auto-appended or manual)** — the
spec does not restrict `RecordTable`'s row-level edit/delete to only manual notes, and
`RecordTable`'s `onEdit`/`onDelete` props are required or every other screen's identical wiring;
editing here only ever changes the entry's `note` text (not its `type`/`contactId`/`dealId`), and
neither action re-triggers `logActivity` (this screen's own mutations are not themselves logged,
consistent with decision (l)'s "does not re-trigger another auto-append" rule for this screen).

```tsx
'use client';
import { useState, type FormEvent } from 'react';
import { RecordTable } from '@portfolio/template-kit';
import type { ActivityLogEntry } from '../data/seed';

export interface ActivityLogScreenProps {
  entries: ActivityLogEntry[];
  onAddNote: (note: string) => void;
  onUpdateNote: (id: string, note: string) => void;
  onRemove: (id: string) => void;
}

const COLUMNS = [
  { key: 'type', label: 'Type' },
  { key: 'note', label: 'Note' },
  { key: 'at', label: 'When' },
];

export function ActivityLogScreen({ entries, onAddNote, onUpdateNote, onRemove }: ActivityLogScreenProps) {
  const [draft, setDraft] = useState('');
  const [editingId, setEditingId] = useState<string | null>(null);
  const [editDraft, setEditDraft] = useState('');

  const sorted = [...entries].sort((a, b) => b.at.localeCompare(a.at));

  function handleAddNote(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    if (!draft.trim()) return;
    onAddNote(draft.trim());
    setDraft('');
  }

  function startEdit(entry: ActivityLogEntry) {
    setEditingId(entry.id);
    setEditDraft(entry.note);
  }

  function handleSaveEdit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    if (editingId) onUpdateNote(editingId, editDraft);
    setEditingId(null);
  }

  return (
    <section aria-label="Activity Log">
      <h2>Activity Log</h2>
      <form aria-label="Add note" onSubmit={handleAddNote}>
        <label>
          New note
          <input value={draft} onChange={(event) => setDraft(event.target.value)} />
        </label>
        <button type="submit">Add note</button>
      </form>
      {editingId ? (
        <form aria-label="Edit note" onSubmit={handleSaveEdit}>
          <label>
            Note
            <input value={editDraft} onChange={(event) => setEditDraft(event.target.value)} />
          </label>
          <button type="submit">Save</button>
          <button type="button" onClick={() => setEditingId(null)}>Cancel</button>
        </form>
      ) : null}
      <RecordTable columns={COLUMNS} rows={sorted} onEdit={startEdit} onDelete={onRemove} />
    </section>
  );
}
```
